Hello Debbie, Yo-Yo, Cameron, Joe, and Donna,

I've been analyzing the system logs, and I believe I've identified the root cause of our recent outages. As you know, we've been experiencing intermittent crashes on the mainframe server. After reviewing the error messages, I think it's due to a memory leak in the application layer. Specifically, the issue seems to be related to the way we're handling nested transactions.

Here are some relevant snippets from my analysis:

```
if (transaction_depth > 0) {
    // Close any open transactions
    for (int i = 0; i < transaction_stack.size(); i++) {
        transaction_stack.pop();
    }
}
```

This code, which is responsible for managing the transaction stack, appears to be the culprit. I've implemented a temporary workaround to prevent further crashes, but we'll need to revisit this code and implement a more robust solution.

I'm available to discuss this issue further if anyone has questions or concerns.
